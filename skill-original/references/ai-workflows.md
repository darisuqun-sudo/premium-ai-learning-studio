# AI Workflows, Agents, and Tool Use

## ۋەزىپىنى بۆلۈش

مۇرەككەپ خىزمەتنى deliverable، subtask، dependency، قوبۇل قىلىش ئۆلچىمى ۋە تەكشۈرۈش باسقۇچىغا ئايرىڭ. ھەر باسقۇچنىڭ چىقىرىشى كېيىنكى باسقۇچقا پايدىلىق بولسۇن. بۆلۈشنىڭ overhead ى پايدىسىدىن ئېشىپ كەتمىسۇن.

1. مەقسەت ۋە success criteria نى ئېنىقلاڭ.
2. مەۋجۇت مەزمۇن ۋە كەم ئۇچۇرنى ئايرىڭ.
3. خەتەر ياكى ئېنىقسىزلىقى يۇقىرى ئىشنى دەسلەپتە تەكشۈرۈڭ.
4. بۆلەك چىقىرىشىنى ئېنىق format بىلەن بەلگىلەڭ.
5. نەتىجىنى مۇستەقىل تەكشۈرۈشتىن ئۆتكۈزۈڭ.

## Tool use ۋە Agent workflow

Agent prompt تا نىشان، ئىشلەتكىلى بولىدىغان tool، tool تاللاش شەرتى، ھوقۇق دائىرىسى، side-effect لىق ھەرىكەتتىن بۇرۇنقى approval شەرتى، retry limit، خاتالىقنى بىر تەرەپ قىلىش ۋە ئاخىرقى دوكلاتنى بەلگىلەڭ. Tool بار دەپ پەرەز قىلماڭ؛ مۇھىتتىن بايقاڭ. قارارنى tool غا بېرىشنىڭ سەۋەبىنى ۋە نەتىجىنى قانداق تەكشۈرۈشنى كۆرسىتىڭ.

ھەقىقىي سىرتقى ئۆزگەرتىش (ئېلخەت يوللاش، publish، delete، deploy، پۇل خەجلەش) ئۈچۈن كۆرسەتمە ئىچىدىكى مەقسەت مۇھىتنىڭ ئىجازەت تەلىپىنى ئالماشتۇرمايدۇ. خەۋپكە ماس stopping condition ۋە recovery ئۇسۇلى بولسۇن.

## Workflow example

**ۋەزىپە:** خېرىدار feedback لىرىنى ئايرىش.

1. تۈرگە ئايرىش: billing / technical / feature / other.
2. ھەر record ئۈچۈن قىسقا دەلىلنى feedback دىن بىۋاسىتە quote قىلماي paraphrase قىلىپ بېرىش، priority ۋە uncertainty قوشۇش.
3. JSON schema غا validate قىلىش.
4. random sample ۋە چېگرا مىساللارنى ئادەم تەكشۈرسۇن.
5. خاتا label لارنى خاتىرىلەپ rubric ياكى مىسالنى يېڭىلاش.

دەلىل يېتەرسىز بولسا «unknown» قايتۇرۇشنى schema دا قوللاش، زورلاپ category تاللىتىشتىن ياخشى.

## Workflow نى كۆزىتىش

نەتىجە بىلەن بىرگە model/tool نۇسخىسى، مۇھىم input/context، output schema نىڭ دەلىلى، human review ۋە error type نى خاتىرىلەڭ؛ لازىمسىز شەخسىي ئۇچۇرنى ساقلىماڭ. ئىقتىدار ئۆزگىرىشىنى كۆرگەندە version comparison reference دىكى سىناق ئۇسۇلىنى ئىشلىتىڭ.
